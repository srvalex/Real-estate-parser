# ============================================================================
# requirements-dev.txt
# ----------------------------------------------------------------------------
# Full local development environment: everything needed to run the Streamlit
# app, the crawler, the full unit test suite (tests/), and every ML model
# used anywhere in the pipeline (SentenceTransformer, CLIP, spaCy) on one
# machine.
#
# This is the union of requirements.txt, requirements-crawler.txt, and
# streamlit_interface/requirements.txt — kept as ONE file for local dev so a
# fresh machine only needs one `pip install`. Those three files still exist
# on purpose and should NOT be merged into this one: they're each scoped to
# a specific Docker image (crawler-job, embedder-job, Streamlit) and staying
# minimal keeps those images small and their dependency surface auditable.
# If you add a new import to code that ships in one of those images, update
# that image's requirements file too, not just this one.
#
# embedding-service/requirements.txt (fastapi/uvicorn) is intentionally NOT
# included here — that's the abandoned always-on Cloud Run Service path
# (superseded by embed_job.py, a plain script with no HTTP server; see
# Roadmap.md tech debt). Add it back only if main.py is revived.
#
# Setup on a new machine:
#   python3 -m venv venv
#   source venv/bin/activate        # Windows: venv\Scripts\activate
#   pip install -r requirements-dev.txt
#   python -m unittest discover -s tests -t . -v
#
# tests/ is organized into per-subsystem suites (tests/scrapers/<platform>/,
# tests/db/, tests/ranking/, tests/crawler/) mirroring the codebase's own
# module layout. Run one suite on its own the same way, e.g.:
#   python -m unittest discover -s tests/db -t .
# The `-t .` (top-level-dir = repo root) is required, not optional: without
# it, unittest computes module names relative to the start-dir instead of
# the repo root, so e.g. tests/scrapers/... would try to import as a
# top-level `scrapers` module and collide with the real scrapers/ package.
# `python -m pytest tests/` also works and doesn't need the equivalent flag.
# ============================================================================
